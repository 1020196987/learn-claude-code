# Learn Claude Code · 从 0 到 1 学习章节

> 本目录是 `learn-claude-code` 仓库的从 0 到 1 学习导读。仓库用 20 个递进式 Python 教学代码（`s01`–`s20`）拆解并重组 Claude Code 的 harness 机制；这一系列导读带你按章节精读每章的设计动机、机制取舍、以及与 Claude Code 生产版（CC 源码）的差异。

---

## 0. 这是什么仓库、这套导读是什么

`learn-claude-code` 的核心论点只有一句话：**Agency 来自模型；Agent 产品 = 模型 + Harness**。

模型负责决策（要不要调工具、调哪个、参数是什么）；harness 负责把环境、工具、权限、记忆、团队、外部能力组织好，让模型能落地行动。仓库的 20 个章节用一个 `while True` 的最小循环作为种子，每章加一个 harness 机制：

```
s01  一个循环 + 一个 bash = 一个 Agent
s02  dispatch map 多工具分发
s03  工具执行前的权限闸门
s04  扩展点 hooks：循环外挂在循环上
s05  计划：todo_write
s06  子 agent：干净上下文的临时工
s07  技能按需加载，不堆 system prompt
s08  上下文压缩管线
s09  跨压缩、跨会话的记忆
s10  system prompt 运行时组装
s11  错误恢复
s12  任务系统：DAG + 持久化
s13  后台任务
s14  cron 调度器
s15  团队 + 文件收件箱
s16  队友协议
s17  自治认领
s18  worktree 目录隔离
s19  MCP 外部工具协议
s20  把 19 个机制合回一个循环
```

这套导读的定位：

- **给 Claude Code 使用者**：你已经用过 Claude Code，但对它的内部架构好奇。这套导读把"为什么会有这种行为"翻译成"harness 在背后做了什么"。
- **讲解设计与动机，不逐行读代码**：每章聚焦于"为什么这么做"、"机制之间如何叠加"、"教学版与生产版的差异"。Python 代码只用于点出关键改动点，不做逐行串讲。
- **对照 CC 源码**：每个章节末尾都有"深入 CC 源码"一节（在仓库原 README 中），导读会引用关键差异，让你知道教学简化藏在哪里。

## 1. 怎么读

**推荐路径**：按顺序 `s01` → `s20`。每章在原循环之上加一层机制，叠加是有因果的：没有 s02 的 dispatch，s03 的权限没有挂在哪个工具上；没有 s05 的计划，s06 的子 agent 就没有任务粒度。

**横向阅读**：如果你已经熟悉 Claude Code 的某个子系统（比如 memory、subagent、MCP），可以直接跳到对应章节，再回头补依赖项。

**动手实验**：每一章都可以 `python sXX_xxx/code.py` 跑起来。README 给出了推荐 prompt 和观察重点；这套导读会标注每章最值得亲手验证的 1–2 个实验。

## 3. 两条线索的对照

仓库原 README 在 `s01_agent_loop/README.md` 等每章都写了完整的"问题 → 解决方案 → 工作原理 → 相对上一章的变更 → 试一下 → 深入 CC 源码"。这套导读**不重写这些**，而是：

1. **重新组织结构**：原 README 是教材体，按"问题驱动"组织；导读更偏"工程师的笔记"，按"机制动机 + 关键改动点 + CC 差异"组织。
2. **强调叠加关系**：仓库每章自包含，导读更强调"这一章的机制挂在上一章的什么位置"，让叠加关系显式。
3. **指向代码改动点**：导读里会点出"循环只改了 N 行"、"新增了哪些工具/状态/线程"等具体改动，让你能直接翻到对应位置对照。
4. **不展开 Deep Dive**：原 README 末尾的 "深入 CC 源码" 章节（几百到上千行的源码分析）保持完整，导读只摘录与本章核心相关的 2–3 条 CC 差异，避免重复。
